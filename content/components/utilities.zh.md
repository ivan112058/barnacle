工具类是库里最小、也最容易被长得太大的一部分，所以它被封顶在五组共二十个类。这里的工具类是一条值得重复
的决定（「把这个居中」、「把那个推开一步」），而绝不是「一个取值配一个类」的属性。

```html
<p class="bn-text-center">Centred text.</p>
<ul class="bn-list-none">
  <li>No marker, no invented indent.</li>
</ul>
```

### 文本对齐

`.bn-text-start`、`.bn-text-center`、`.bn-text-end`。用的是逻辑值而不是 `left` 与 `right`，所以从右到左
的页面不需要额外规则。

### 仅供屏幕阅读器

`.bn-visually-hidden` 是唯一的无障碍工具类，也是库里唯一让东西变不可见的类。它把内容留在无障碍树里，并
保持它可聚焦——而 `display: none` 与 `visibility: hidden` 两样都会把这些丢掉：可见文字是一个图标时用它
做控件的标签，或者用在一个给屏幕阅读器组织页面、却不出现在页面上的标题。

### 布局组合

四种固定的排布，每一个都是一条决定，而不是一堆属性：

`.bn-stack` 把子元素排成一列，之间的间隙只有一个；`.bn-cluster` 把它们在一行里换行，并在交叉轴上居中；
`.bn-center` 把一个东西上下左右都居中；`.bn-between` 把第一个与最后一个子元素推开。`bn-stack`、
`bn-cluster` 与 `bn-between` 如果你设了 `--_stack-gap` 就读它，否则用各自的默认值。

凡是要分列的场合，去用布局页上那套栅格——`bn-col-*` 承载尺寸，而这四个只负责排布栅格里面的东西。

```html
<div class="bn-between">
  <span>A label</span>
  <span>A value</span>
</div>
```

### 块间距

八个类：两个方向上各四步。`.bn-mt-2`、`.bn-mt-4`、`.bn-mt-8`、`.bn-mt-16` 以及对应的 `.bn-mb-2`、
`.bn-mb-4`、`.bn-mb-8`、`.bn-mb-16`，分别对应 `0.5rem`、`1rem`、`2rem` 与 `4rem`。这些数字是刻度的
名字，不是像素值：`2 / 4 / 8 / 16` 是一条翻倍的梯子，而一个需要在两个元素之间留 `0.7rem` 的页面，是一个
该自己写 margin 的页面。

它们设的是 `margin-block-start` 与 `margin-block-end`，所以在任何书写模式下行为都一样。

### 尺寸与文本

`.bn-w-full` 让元素填满容器的行内尺寸。`.bn-truncate` 把它限制在一行并以省略号结尾——而且因为它同时重置了
自动最小尺寸，它在 flex 或 grid 项里也能生效，而不是把那项撑破。

`.bn-list-none` 同时去掉列表标记和「没有标记的列表本来会保留」的起始内边距，这使它成为下面那条层规则最
清楚的例子。

`.bn-text-muted` 从 `--bn-foreground` 派生出颜色来弱化文本，所以它会随主题翻转，而不是在深色背景上变成
看不见的灰。

### 边界

二十个类，而这条线画在三个地方。

除了那四步间距，不设任何数值轴。完全不设响应式前缀：一个 `bn-md-*` 家族会等于这个列表乘以断点数量，而一个
需要断点的页面已经有栅格，或者有自己的媒体查询。也不设颜色、边框或阴影：那些是库的视觉修饰——`.bn-outline`、
`.bn-ghost`、`.bn-sm`、`.bn-lg`、`.bn-attached`、`.bn-icon`——一个与其中某个名字重名的工具类会悄悄重定义
一个组件的形状，而不是把它挪一下。

### 它们为什么赢，以及怎么赢过它们

库里的每条规则都在级联层里，而 `utilities` 是最后一层（ADR-0006）。所以工具类能赢过库内的组件或基础层
规则，既不需要 `!important`，也不需要争论特异性——`.bn-list-none` 覆盖 `ul { list-style: square }` 是
同一套机制，不是特例。

同一条 ADR 也为你想好了另一个方向：**不分层的 CSS 赢过每一个层。** 在库之后加载、里面没有 `@layer` 的
样式表，不用 `!important` 就能覆盖这些类中的任何一个——或者任何一个组件。这也是为什么这二十个类同样一个
都不需要它。
