# Barnacle

A semantic-first Neubrutalism UI library in pure CSS. Zero runtime dependencies, no shadow
DOM, no class-name API: you write the HTML element that already means what you mean and
Barnacle styles it.

> **Status: v1 in progress.** The build chain (ticket 01), this documentation site's skeleton
> (ticket 02), its demo rendering layer (ticket 04) and the GitHub Pages deploy workflow
> (ticket 03) are in place. Components, theme tokens and the full site content land in later
> tickets, so the page styles are still placeholders.

## Repository layout

```
seite.toml        seite configuration — base_url points at the Pages sub-path /barnacle/
content/          docs content: Markdown + YAML frontmatter
  pages/          /, /usage, /customizing
  components/     /components/ index + one page per component
templates/        Tera templates (seite resolves collection indexes as <collection>-index.html)
static/           committed build output + the docs site's own style.css
  barnacle.css    src/css/*.css concatenated, in the layer order of ADR-0006
  barnacle.min.css
  barnacle.js     src/js/index.js bundled as an IIFE
  barnacle.min.js
  style.css       docs site styling only — never mixed into the library
  site.js         docs site behaviour only: fences → Preview/Code pairs, theme switch
public/           copied to the root of dist/ (favicon, .well-known, CNAME, …)
src/              library sources (css/ and js/) — not part of the published site
scripts/          build.mjs, verify.mjs, verify-theme.mjs, verify-site.mjs,
                  verify-demo.mjs, verify-deploy.mjs
docs/             ADRs and agent docs
dist/             generated by seite, gitignored
```

The published artifacts live in `static/`, not `dist/`: seite copies `static/` verbatim into
`dist/static/`, so one committed file is simultaneously the docs site's asset, the artifact
published with the repository, and the file jsDelivr can serve from the `main` branch.

## Library build

```powershell
npm install
npm run build     # src/ → static/barnacle{,.min}.{css,js}
npm run verify    # 21 build-chain checks (ticket 01)
```

`npm run build` fails loudly rather than emitting broken CSS: a file listed in
`scripts/build.mjs` that is missing on disk, or whose `@layer` placement breaks the
ADR-0006 contract, aborts the build with the offending file named.

## Documentation site

`seite` is **not on `PATH`** on this machine. Always call it by its absolute path:

```powershell
# local preview with live reload — http://127.0.0.1:4377
& "D:\sdk\seite\seite.exe" serve --port 4377

# one-off build into dist/
& "D:\sdk\seite\seite.exe" build

# link/asset validation; --strict turns warnings into a non-zero exit
& "D:\sdk\seite\seite.exe" check --strict
```

`seite serve` prints on stderr and serves from the origin root, so the preview URL is
`http://127.0.0.1:4377/` — **not** `/barnacle/`. Templates therefore reference every asset
through `{{ site.base_url }}`, which is the production sub-path when built and the dev
origin when served.

### Verifying the site

```powershell
node scripts/verify-site.mjs
```

This runs the checks ticket 02 promises: `seite build` and `seite check --strict` both clean,
the four published artifacts byte-identical between `static/` and `dist/static/`, every page
asset sub-path safe and present in `dist/`, every internal link resolving, the repository's
`AGENTS.md` untouched by the seite scaffold, `seite init`'s file list re-measured, and the
preview server actually serving `/` and `/components/`.

`node scripts/verify-site.mjs --minify-experiment` additionally builds with `minify = false`
and `minify = true` and prints the byte comparison. It is why `seite.toml` keeps
`minify = false`: with `true`, seite re-compresses the already-minified CSS and drops the
trailing newline from the JS, so `dist/static/` would no longer match the committed
artifacts.

### Verifying the sub-path deploy

```powershell
npm run verify:deploy
```

`seite serve` cannot reproduce the deployed layout — it always serves from the origin root —
so this script serves `dist/` itself under `/barnacle/`, the mount GitHub Pages uses for a
project site, and then requests every `href`/`src` on every built page. It fails on any
reference that leaves the `/barnacle` root, any non-200 (the four artifacts, `style.css` and
the favicon included) and any served file whose bytes differ from the committed one. It also
asserts the contents and step order of `.github/workflows/deploy.yml`. `--no-serve` and
`--no-build` skip the two halves.

### Verifying the demo rendering layer

```powershell
node scripts/verify-demo.mjs
```

Ticket 04's checks: a component page's Markdown fences become Preview / Code pairs, the code
panel shows the fence source escaped, the Preview/Code tabs are keyboard operable, component
pages render exactly one H2 (the one the template supplies), and the header theme switch sets
`data-theme` on `<html>` and survives a reload. Authoring stays plain Markdown — a fence that
does not start with `<` stays a plain code block.

The last five checks drive real Chrome over the built site on `/barnacle/`. They need
`playwright-core`, which is deliberately **not** a dependency of this repository (ticket 08
owns that decision), so install it for a local run and nothing is written to `package.json`:

```powershell
npm i --no-save playwright-core@1.64.1
node scripts/verify-demo.mjs          # or: npm run verify:demo -- --no-browser
```

Without the module the browser checks report `SKIP` and the static checks still gate the exit
code.

## Deployment

`.github/workflows/deploy.yml` is seite's own GitHub Pages workflow (`upload-pages-artifact@v3`
+ `deploy-pages@v4`, no `gh` CLI) with the build chain inserted ahead of it, on every push to
`main`:

`actions/setup-node@v4` (Node 26) → `Install seite` pinned via `VERSION=v0.20.1` with
`$HOME/.local/bin` appended to `$GITHUB_PATH` → version assertion → `npm ci` →
`npm run build` → `git diff --exit-code -- static/` (the committed artifacts must be exactly
what CI rebuilds) → `scripts/verify.mjs` → `scripts/verify-theme.mjs` →
`scripts/verify-site.mjs` → `seite build --strict` → `seite check --strict` → upload `dist/`.

`seite upgrade --check` is never run in CI: it always exits non-zero because it wants to write
agent scaffolding.

**One-time repository setting:** Settings → Pages → Build and deployment → Source must be
**GitHub Actions**. Without it the deploy job fails, and the setting cannot be committed — it
is changed in the UI or with `POST /repos/ivan112058/barnacle/pages` and
`{"build_type": "workflow"}`.

## Consuming the library

```html
<link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/ivan112058/barnacle@main/static/barnacle.min.css">
<script src="https://cdn.jsdelivr.net/gh/ivan112058/barnacle@main/static/barnacle.min.js" defer></script>
```

The unminified pair (`static/barnacle.css`, `static/barnacle.js`) is published alongside it.
v1 does not publish to npm.
