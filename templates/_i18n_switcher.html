{#- The language switcher (ticket 23). Exactly one link: to the same page in the other language. `translations` is always defined but may be empty. It is populated for pages that have a counterpart — each entry is {lang, url}, the current language included, and the url already carries the /zh prefix (measured: /usage and /zh/usage both report [{en,/usage},{zh,/zh/usage}]) — so it is the source of truth. Exception, measured: seite does NOT populate translations for a collection index (/components/ and /zh/components/ both report []), even though content/components/index.zh.md exists. Those pages are recognised by page.slug == page.collection ("components"/"components"; a component page is "button"/"components", a plain page "usage"/"pages"), and their counterpart URL is derived from page.url — the only place in the site where a URL is computed rather than read. scripts/verify-i18n.mjs asserts that every switcher target exists in dist/. A page with no counterpart gets no switcher at all, not an empty box: the group is inside the `if`, because `.site-lang` draws a border and a background. That is the 404 pages, today. Tera note: Tera has no ternary operator, hence set_global + if. -#} {%- set_global other = "en" -%} {%- if lang == "en" %}{% set_global other = "zh" %}{% endif -%} {%- set_global other_url = "" -%} {%- for translation in translations -%} {%- if translation.lang == other %}{% set_global other_url = translation.url %}{% endif -%} {%- endfor -%} {%- if other_url == "" and page.slug == page.collection -%} {%- if lang == "en" %}{% set_global other_url = "/zh" ~ page.url %}{% else %}{% set_global other_url = page.url | replace(from="/zh", to="") %}{% endif -%} {%- endif -%} {%- if other_url != "" -%}
