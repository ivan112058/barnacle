---
title: "下拉菜单"
description: "基于原生 popover API 的菜单。你写触发器与面板；这个元素补上键盘、焦点处理、锚定与事件。"
---

`bn-dropdown` 增强你已经写好的标记，而不是替你造一个菜单。给一个按钮写上 `popovertarget`，给它指向
的面板写上 `popover` 属性，浏览器就会打开它、锚定它，并在点到外面时关掉它——关掉 JavaScript 也一样。
这个元素补的是平台留下的空缺：方向键导航、打开时进入菜单而关闭时回到触发器的焦点，以及三个可监听的事件。

<!-- fence:0 -->

那段标记里没有一样东西是生成的：没有 shadow root，没有克隆的节点，没有背着你造出来的 id。面板是这个
元素真正的子元素，所以样式表可以用普通的后代选择器指到它。如果契约缺了任何一块——没有 `popovertarget`、
`id` 解析不到东西、目标上没有 `popover`——这个元素就什么都不做、也什么都不说：不报错、不打日志、也不
尝试修复。

### 这个元素补了什么

在打开的菜单里，方向键在各项之间移动并在两端循环，`Home` 与 `End` 跳到第一项与最后一项，而且恰好只有
一项留在 Tab 顺序里，其余只能用方向键到达。`Esc` 关闭菜单并把焦点交回触发器；选中一项也一样。从菜单里
Tab 出去同样会关掉它，而不是把它留在页面上飘着。发生在别处的关闭——点到外面，或者平台自己的轻量关闭
——会把焦点留在访客放它的地方，而触发器上的 `aria-expanded` 永远报告真相。

### 事件

这个元素宣告的一切都是会冒泡、能穿过 shadow 边界的 `CustomEvent`，与库的其它部分保持一致。要知道有东西
被选中，监听是唯一的办法。

<!-- fence:1 -->

| 事件 | 触发时机 | `detail` |
|---|---|---|
| `bn:open` | 面板已经打开，无论用什么方式 | `{ trigger, panel }` |
| `bn:close` | 面板已经关闭，无论用什么方式 | `{ trigger, panel }` |
| `bn:select` | 有一项被点击或激活 | `{ value, item }` |

`value` 是那一项的 `value` 属性（如果有的话），否则就是它的文本，所以一列只写了标签的普通按钮菜单完全
不需要记账用的属性。`item` 是那个元素本身，用于光有 value 不够的场合。

### 菜单项

菜单项就是任何带 `.bn-dropdown-item` 的可聚焦元素——几乎每次正确答案都是 `button`，但让它成为菜单项的
是这个类；一项可以包含别的元素，只要它不包含第二个项。`value` 属性是可选的。用 `aria-selected="true"`
标记已经生效的选项，或者用 `aria-checked="true"` 标记被切换开的那一项；两者都会把这一项涂成强调色，
不需要任何额外的类。

<!-- fence:2 -->

### 它怎么摆放

面板靠 CSS 锚点定位摆在触发器下面，而不是靠一个 `position: relative` 的包裹元素：popover 渲染在顶层，
在那里 `position: absolute` 是相对页面解析的，而不是相对你嵌套它的那个元素。浏览器会给 popover 一个
隐式锚点——就是唤起它的那个按钮——只要菜单是由点击或按键打开的，这就够了。这个元素还会显式地命名那个
锚点，每个实例一个唯一名字，所以同一个页面上的两个下拉菜单不会互相偷位置，程序化打开也落在同一个地方。
没有脚本时 CSS 仍然找得到隐式锚点，面板仍然出现在触发器下面。

### 覆盖它

面板与菜单项读的令牌与别处完全一样，这里没有任何一条规则自带颜色或距离。
`--bn-secondary-background` 设定面板的表面，`--bn-main` 设定悬停或选中项上的高亮，而
`--bn-shadow-md` 是面板的硬阴影，`--bn-border-width` 是它的边框。你自己写的不分层 CSS 赢过库发布的
每条规则，所以覆盖不需要 `!important`；记得把令牌改在 `:root` 上，因为派生令牌在它被声明的地方就已经
替换完毕。
